# 模型从哪里获取：3D 模型资源与 Mod 制作指南

找模型时，不要只搜“角色名 + 模型”。**先确定用途，再筛选格式，最后确认授权**，通常比盲目下载更有效。本页整理国内外模型库、商城、MMD / VRChat 社区、写实角色资源、成人向资源入口，以及打印、扫描、CAD 和 AI 生成等补充途径。

> 整理与入口核查日期：**2026-10-02**。网站、价格、授权和下载政策会变化。本页是持续维护的导航，**不承诺穷尽互联网，也不保证每个网站或每件资产都能下载、商用或用于 Mod**。

::: warning 先看授权，再开始转换
免费、购买、订阅、可商用、允许修改、允许用于游戏、允许成人向用途、允许随 Mod 再发布，是不同的权限。把模型转换成 PMX、FBX 或游戏格式，不会自动获得新的授权。

本页只提供中性的资源导航，不展示成人内容，不收录盗版付费资源镜像、泄露订阅包或绕过下载限制的方法。成人向用途仅限合法的成年人角色与内容；未成年人及年龄不明的角色不适用。
:::

## 如何阅读资源表

- **费用**是常见模式，不是价格保证：“免费 / 付费”不代表站内所有资源都免费。
- **格式**是选型提示，不代表每件商品都有这些格式；购买前以商品页和实际交付清单为准。
- **SFW**表示这里推荐的是普通素材用途，不保证整个站点没有人体、血腥或成熟内容。混合平台的分级见成人向章节。
- **入口核查**仅检查公开网页响应、标题或官网说明，**没有购买、登录、下载或逐模型检查**。
- **受限**表示核查遇到 403、人机验证或账号门槛，不等于网站失效；**待核**表示网络失败或身份、内容尚未充分确认。
- 无“受限 / 待核”标记的模型目录已取得公开页面响应；作者商店、展示社区和检索站会明确说明，不能当成统一下载库。

### 中文社区也可以找原作者

[哔哩哔哩](<https://www.bilibili.com/>)、[米游社](<https://www.miyoushe.com/>)、[知乎](<https://www.zhihu.com/>)及游戏官方活动页，有时会发布模型配布公告、创作者主页和委托信息。它们是**作者线索 / 公告渠道，不是统一模型库**。

优先从官方账号的公告进入原始配布页。不要因为资源标题写着“官方模型”，就忽略只允许 MMD 视频、禁止商业使用或禁止转入其他游戏等限制。国内成人向资源不做无依据的站点推荐，应遵守当地法律及平台规则。

### MMD / VRChat 模型最容易踩的坑

1. **“允许改造”不一定允许转游戏。** MMD 作者常会单独限制游戏、商业、暴力、成人用途及再配布。
2. **服装商品不一定附送人体。** 很多衣服仅适配某个付费基础角色，必须分别取得两者授权。
3. **Unity 包不等于通用 FBX。** 可能只带 Prefab、材质、Shader 或依赖；先看是否提供原始网格。
4. **角色能在 VRChat 使用，不等于能在 Mod 平台发布。** 公开文件、公开 Avatar、私人 Avatar 和跨游戏移植可能是四种不同权限。
5. **VRM 中的授权元数据也要保留。** 使用条件仍须结合作者页面，不能靠转换格式去掉限制。

### 成人向 Mod 的实用选择顺序

1. **优先找原创成年人角色，并要求作者明确授权你的用途。** 授权至少覆盖转游戏、改造、成人用途及具体分发方式。
2. **再看通用基模与人体素材。** 检查皮肤、身体、头发、衣服是否分别来自不同作者；许可要逐层满足。
3. **最后看既有 Mod 的资源依赖。** 优先使用作者明确标为 modder's resource 的资产，或让用户安装原始前置；不要复制别人的付费包。
4. **许可不清楚时委托制作或自行建模。** 不应把“成人向”当成可以忽略版权、年龄和肖像同意的理由。

- **本地研究与公开发布是不同的问题。** 游戏 EULA、当地法律、作者权限及分发方式都可能影响能否使用；不能一概认定“买了游戏就能搬”。
- **优先使用官方 Mod SDK、官方开放资产或明确允许制作资源复用的包。** 移植前检查源游戏与目标游戏双方规则。
- **不要直接复制其他作者的 Mod 并署自己的名字。** 身体、衣服、贴图、骨骼和物理配置可能有不同作者。
- **前置依赖可以减少复制，但不能自动解决授权。** 即使要求用户安装原包，派生补丁也可能仍受限制；不确定时联系作者。
- **不收录整合盗版游戏、付费 Mod 泄露包或订阅内容镜像。** “方便下载”不能代替合法来源。

### Koikatsu / Koikatsu Sunshine 等角色编辑游戏

原文提到过恋活模型转换。这属于**特定游戏资产工作流，而不是开放模型下载网站**：

- 角色卡通常保存外观参数、服装配置等数据，**不是独立 FBX / PMX 模型**，还可能依赖游戏本体和第三方 Mod。
- `.zipmod` 通常是 ZIP 容器，其中可能有 Unity AssetBundle、配置和其他内容；**改扩展名不会自动变成可直接导入 Blender 的模型**。
- KKBP、KKPMX 等工具属于特定版本的转换工具；导出功能、维护状态、Blender 兼容性及依赖要另查。
- 即使成功导出，也要分别确认游戏资产和每个 Mod 作者的改造、成人用途与再发布权限。这里不提供整合游戏下载源。

### 原作者确认方法

## 下载、转换和发布检查清单

### 先看格式，避免买错

| 格式 / 交付 | 通常包含什么 | 对 Mod 的意义 |
| --- | --- | --- |
| FBX | 网格、骨骼、权重、部分动画 / 材质信息 | 常用交换格式，但仍要改目标骨骼、材质和导出设置 |
| glTF / GLB | 网格、PBR 材质、贴图、可选骨骼和动画 | 方便预览 / 交换；目标游戏不一定直接支持 |
| OBJ | 静态网格、UV，可附 MTL | 通常不含标准骨骼和动画，角色往往需重新绑定 |
| BLEND | Blender 场景、模型和相关数据 | 检查贴图是否打包、版本和外部依赖；不要启用不明 Python 脚本 |
| PMX / PMD | MMD 模型、材质、骨骼、形态键、物理等 | 可用 mmd_tools 等导入；MMD 物理 / Shader 不会自动等价转成游戏配置 |
| VRM | 角色、骨骼、材质、表情与授权元数据等 | 通过合适的 VRM 工具转换；许可与元数据应随来源记录保留 |
| Unity package / 工程 | 资源、Prefab、材质、脚本、依赖等 | 确认含源网格；Shader、插件和引擎版本可能限制使用 |
| MAX / MA / MB / C4D | 对应 DCC 的场景和模型 | Blender 不能直接原生打开所有格式；购买前要求 FBX / OBJ 等交付 |
| DUF / Daz 内容 / CC 内容 | 特定角色生态的数据、形态和素材 | 通常需要相应软件、基础角色及导出许可 |
| STL / 3MF | 打印网格与可能的打印 / 颜色信息 | 通常没有游戏用 UV、PBR、骨骼，需要重拓扑和绑定 |
| STEP / IGES / BIM | CAD 曲面、工程参数、构件等 | 先转多边形网格，再处理 UV、细节、碰撞和实时性能 |
| VMD / BVH / 动画文件 | 动作、骨骼运动或姿态数据 | 不是角色网格；动作授权与模型授权分别确认 |

### 下载或购买前

- [ ] 明确是角色、衣服、头发、静态道具、场景、动画，还是只含预览图 / 教程。
- [ ] 确认格式、软件版本、贴图是否齐全、基础模型和付费插件依赖。
- [ ] 检查三角面数、骨骼、权重、形态键、LOD、UV、材质槽数量和贴图尺寸。
- [ ] 确认允许转游戏、修改、预期商业方式，以及是否允许随 Mod 分发。
- [ ] 成人向项目另外确认成年人设定、用途授权、肖像同意和平台分级。
- [ ] 保存作者、来源、许可版本与订单；许可不明先询问，别先做完再谈授权。

### 导入到 Blender 或目标制作工具后

- [ ] 检查比例、坐标轴、法线、镜像、重复面、隐藏部件和非流形问题。
- [ ] 区分渲染高模与实时低模；按目标游戏处理减面、重拓扑、法线烘焙和 LOD。
- [ ] 重建目标游戏的材质，核对贴图色彩空间、透明、法线方向与通道打包。
- [ ] 映射目标骨骼，限制每顶点权重数，测试肩、肘、髋、膝与手指等关节变形。
- [ ] 检查衣服穿模、表情、物理、碰撞和游戏中的实际性能。
- [ ] 角色卡、材质预设、动作包和 Shader 都不能被当作独立角色网格。

### 发布前

- [ ] 再次核对每个组成部分的许可，尤其是身体、头发、衣服、纹理、动作和第三方 IP。
- [ ] 确认许可覆盖当前分发方式：免费 Mod、付费 Mod、赞助奖励、补丁或前置依赖。
- [ ] 在发布页注明作者、来源、所用许可、修改内容及必要前置，按许可附带署名和说明。
- [ ] 不附带未经许可的原始源模型、付费基础包、平台下载凭据或个人资料。
- [ ] 内容标注 / 年龄分级符合目标游戏、Mod 平台和所在地规则。

## 授权速查与官方说明

以下只是选型提示，不是法律意见。必须以适用许可全文、商品补充条款和权利人的有效授权为准。

| 许可 / 规则 | 一般含义 | 用于 Mod 时的关键点 |
| --- | --- | --- |
| [CC0](<https://creativecommons.org/publicdomain/zero/1.0/>) | 尽可能放弃版权 / 数据库权利 | 常适合改造和再发布；仍不清除肖像、商标、隐私或第三方版权 |
| [CC BY 4.0](<https://creativecommons.org/licenses/by/4.0/>) | 可分享和改作，包括商业用途，须署名 | 保留作者、许可链接、来源与修改说明；不能施加冲突限制 |
| [CC BY-SA 4.0](<https://creativecommons.org/licenses/by-sa/4.0/>) | 署名，改作需按相同条件共享 | 注意改作资产的同许可要求及与其他资产条款的兼容性 |
| [CC BY-NC 4.0](<https://creativecommons.org/licenses/by-nc/4.0/>) | 限非商业用途，须署名 | 付费 Mod、赞助专属、广告 / 营利等场景不能仅凭“免费下载”认定合规 |
| [CC BY-ND 4.0](<https://creativecommons.org/licenses/by-nd/4.0/>) | 允许按条件分享未改作材料 | 纯格式转换不必然算改作，但改形、拼装等派生 Mod 不宜在无额外授权下发布 |
| Royalty Free / Standard License | 按具体条款免逐次版税使用 | 不表示任意再配布、出售模型源文件或资产包 |
| Editorial | 限定新闻、评论等编辑用途 | 通常不适合直接用作娱乐游戏或公开角色 Mod |
| 作者自定 / BOOTH / MMD 利用规约 | 可对用途和分发方式分别限制 | 查改造、游戏、商业、成人、再配布；不清楚就请求书面授权 |
| 仅个人使用 / 仅渲染 | 使用范围较窄 | 不要公开发布含该模型的 Mod；截图许可不等于网格许可 |
| 无许可证 / 只写“免费下载” | 没有明确的复用授权信息 | 不应推定可改造或再发布；追溯作者或换明确授权的资产 |

### 应重点阅读的官方条款

- [Poly Haven License](<https://polyhaven.com/license>)：官网说明资产采用 CC0。
- [ambientCG License](<https://docs.ambientcg.com/license/>)：官网说明资产采用 CC0。
- [Blendkit Licenses](<https://www.blendkit.com/docs/licenses/>)：明确区分 CC0 与 Royalty Free，后者不能当作模型自由转售许可。
- [Daz Interactive License 说明](<https://www.daz3d.com/interactive-license-info>)与 [Daz EULA](<https://www.daz3d.com/eula/>)：官方说明游戏等使用 / 分发 3D 数据需要交互许可，并非每件商品都提供。
- [Reallusion Content License Policy](<https://www.reallusion.com/license/content.html>)：本次官网列出 iContent、Standard、Enterprise；不要机械沿用旧教程里只看 Export / Extended 字样的做法。
- [Unity Asset Store Terms / EULA](<https://unity.com/legal/as-terms>)：核对嵌入产品、独立资产分发及特殊资产条件。
- [Fab EULA](<https://www.fab.com/eula>)：本次抓取受限，实际使用前通过浏览器查看适用条款；不同许可 / 历史来源应分别核对。

**对于 Daz、引擎商城或 Royalty Free 资产，公开 Mod 是否符合“嵌入最终产品”及防止独立提取等条款，不能只凭一行“允许游戏使用”下结论。** 最稳妥的是获得覆盖你具体 Mod 分发方式的授权，或改选明确允许再发布的开放资产。

### 如何继续补充

每次新增网站或作者商店，至少记录：**名称、原始入口、资源类型、常见交付格式、费用模式、是否含成熟内容、授权说明、访问状态、核查日期**。

维护时遵循以下原则：

1. 优先保留官网、原作者和官方机构入口，不用网盘转载、短链或订阅镜像替代。
2. 新名称、迁移站和多地区入口说明关系，避免重复凑数量。
3. 403、验证页和登录门槛记为“受限”，超时和 TLS 错误记为“待核”；不能据此断言网站倒闭。
4. HTTP 200 也可能是空白页、停放域名、验证页或完全不同的业务，必须检查标题和内容。
5. 分开记录模型库、展示社区、作者商店、检索站、软件和生成服务，避免误导读者。
6. 不给全站统一贴“可商用 / 可成人向 / 可再发布”标签；这些权限最终要落到具体资产。

**最终目标不是“下载最多”，而是找到来源清楚、格式合适、能在目标游戏中正常运行，并且允许按你的方式发布的模型。**
